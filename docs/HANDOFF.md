# 妍序 Skin 預約系統 交接說明

LINE 預約系統，freelance 案：建置費 NT$20,000、月費 NT$1,000。只有老闆一人服務、不做包堂。

## 技術與部署
- Node.js（>=18）、Express 4、PostgreSQL。CommonJS。
- Railway 專案 `crm-system`，GitHub `Hsulala/skin-crm`（私有）。目前以 zip 解壓縮後拖進 GitHub 網頁「Upload files」，Railway 自動部署。
- 注意：網頁上傳只會新增、覆蓋檔案，不會刪除檔案。要刪的檔案請在 GitHub 網頁上自己刪。
- 測試：`npm test`（node:test，PGlite 當測試資料庫）。
- 啟動時自動套用編號 migration（`migrations/00N_*.sql`）。`schema.sql` 不自動執行。

## 權限
- owner（管理者）：品項價格、時段範本、帳號、問卷與代碼結構、預約開放範圍、功能模組與店家設定。
- staff（操作人員）：日常操作，看不到上述管理項目。

## 功能模組與店家設定
- 存在 `store_config`（key / value JSONB），沒存過的用程式內預設值（既有功能預設開）。
- 模組：`revenue`、`skinRecord`。關閉時 API 回 403、側邊欄標示「未開通」、資料保留。
- 寫入只動有帶的欄位，未知的 key 保留；異動寫入 `config_audit`。
- 設定 API 目前只供後台使用。之後 CRM 要遠端管理，需要另外加「用金鑰保護、讀寫分開」的介面（規劃中，尚未做）。

## 電腦版後台導覽
- 左側三組：主要（月曆總覽、本週時段表、客戶管理）、營運（營收明細、預約開放範圍、時段範本設定）、設定（品項管理、皮膚紀錄欄位設定、子帳號管理、帳號設定、功能模組）。
- 側邊欄項目沿用既有按鈕的處理程式（`data-proxy`），所以原本的功能邏輯沒有動。
- 手機版維持底部導覽列與「更多」面板，「更多」多了「功能模組」。
- 色調沿用既有 CSS 變數；設定主題色後會同步改 `--accent`、`--accent-strong`、`--accent-soft`。

## 合作慣例
- 一律繁體中文；給客人看的文字不用表情符號，用【】、◆、▸。
- 新功能先查現有程式再改；不可覆蓋店家已存的設定。
- 交付：zip，先在乾淨 clone 驗證可套用、測試全過，檔名唯一。

## 已知限制與待辦
- 客人 LIFF 頁的店名與主題色尚未跟著設定走（目前只有後台）。
- 後台既有畫面裡還有少量表情符號與箭頭（例如公休標記、已完成標記），尚未統一換成文字符號。
- 沒有全域的後台稽核紀錄，目前只有設定異動有紀錄。
- 規劃中：CRM 遠端管理介面、資料表加 `store_id`（合併成共用服務時再做）。

## 第一次套用這個版本要做的事
1. 在 GitHub 刪除根目錄的 `server.js`、`line.js`、`webhook.js`（舊版殘留，執行入口是 `src/server.js`，這三個檔案沒有被使用）。
2. 上傳新版 zip 解壓縮後的內容。
3. Railway 自動部署後，日誌應出現：`[server] 已套用 migration：002_store_config.sql`。
